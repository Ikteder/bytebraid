## Explicit improvement run

- The user approved the recorded next improvements: hard-link identity and a disk-backed chunk index.
- Physical identity uses Windows volume/file IDs or POSIX device/inode pairs. Fingerprints are reused for aliases, but all logical paths remain visible in reports.
- Exact groups now expose physical-copy count and per-group reclaimable bytes. A hard-link-only group is not an exact-copy group and reports zero reclaimable bytes.
- Near indexing selects one canonical logical path per physical identity, preventing redundant alias/revision pairs.
- Disk indexing spills fixed-width postings into 64 hash partitions by default and removes its unique temporary child after processing.
- The first disk metric counted only the largest loaded partition and omitted write buffers. It was rejected before documentation; the final metric is peak resident posting records across buffers or a loaded partition.
- The 2.50 MiB demo has six logical paths, five eligible paths, four physical eligible files, one hard-link group, two physical exact copies, two near pairs, and 512 KiB conservative reclaimable storage.
